# 更新賃料検討アプリ

賃貸住宅の更新時に、**いくらで提示すれば貸主と借主の双方が成立するか**を検討する道具です。

周辺の募集条件から対象住戸の賃料水準を求め、**双方が成立する賃料の幅**を出します。
その幅の中から提示額を選ぶのは人の判断で、アプリは推奨額を出しません。

作れるもの: **借主向けの提案資料**（PDF）／**貸主向けの検討資料**（PDF）／**借主へ送るメールの下書き**（AI用の文章）

---

## 1. 最初の1回だけ必要な準備

### Node.js を入れる

このアプリは Node.js の上で動きます。入っているか確認します。

ターミナル（Mac なら「ターミナル」、Windows なら「PowerShell」）を開いて、次を打ってください。

```
node -v
```

`v22.0.0` のように表示されれば入っています。`command not found` と出たら、
[nodejs.org](https://nodejs.org/) から **LTS** と書かれたほうをダウンロードして入れてください。

> **必要なバージョン: 20 以上**（開発は 22 で行っています）

### このアプリを取ってくる

```
git clone https://github.com/tomoshigeta/rent-assessment.git
cd rent-assessment
```

### 部品を入れる

```
npm install
```

数分かかります。1回やれば次からは不要です。

## 3. 使い方

**アプリの画面を開くと、一番上に「使い方」が表示されます。** 手順ごとの説明はそちらにあります。
ここでは全体の流れだけ示します。

```
① 入力シート（Excel）をダウンロードして、募集図面を見ながら記入する
        ↓
② アプリでそのファイルを読み込む
        ↓
③ 原状回復費用と空室期間を入れる
        ↓
④ 賃料の幅が出る。その中から提示額を決める
        ↓
⑤ 資料（PDF）とメールの下書きを出す
```

### 入力シートについて

画面からダウンロードできます。シートは2枚です。

| シート | 書くこと | 必須の列 |
| --- | --- | --- |
| **対象物件** | 更新を検討している部屋。**1行だけ** | 物件名・現在家賃・現在管理費・面積 |
| **比較事例** | 周辺の募集中物件。**5件以上** | 物件名・賃料・管理費・面積・募集元・確認日 |

**2行目は記入例なので消さずに残し、3行目から書いてください。**

金額は**すべて税込**で、家賃と管理費は分けて書きます（アプリが合算します）。
管理費がなければ 0 と書いてください。空欄にはしないでください。

記入済みの見本 `更新賃料検討_入力シート_記入例_麻布十番.xlsx` も画面からダウンロードできます。
実際の募集図面6件のデータが入っているので、**まずこれを読み込んで動きを見るのが早い**です。

### 一番大事なこと

**比較事例をどう選ぶかが、結果を最も左右します。**

アプリは**面積の違いしか揃えません。** 築年・階数・向き・設備の差は補正しないので、
**条件の近い物件だけを、あなたが選んでシートに書いてください。**
書いた行はすべて集計に入ります。

実データで確かめたところ、同じエリア・同じ面積帯でも**築年が20年違うと㎡単価が1.5倍以上開きました。**
混ぜて入れると、その分だけ結果がずれます。

### 保存について

**このアプリは案件を保存しません。記入した Excel が保存データそのものです。**

条件を変えて検討し直すときは、Excel を直して読み込み直してください。
差出人の連絡先だけはブラウザが覚えています。

## 4. 何が出てくるか

```
      貸主側の下限                         借主側の上限
         │                                    │
   ──────┼────────────────────────────────────┼──────
         │      この範囲なら双方が成立         │
    これを下回ると                      これを上回ると
    再募集したほうが得                  借主は転居したほうが得
```

| | 意味 |
| --- | --- |
| **査定賃料** | 比較事例の㎡単価の中央値 × 対象物件の面積。今募集したら付くはずの賃料 |
| **貸主側の下限** | これを下回ると、退去させて再募集したほうが得になる額 |
| **借主側の上限** | これを上回ると、借主は転居したほうが得になる額。**現在賃料の約14.9%増**が目安 |
| **r（掛け目）** | 提示額 ÷ 査定賃料。1.00 が査定どおり |
| **逆転月** | その提示額なら何ヶ月目から転居のほうが安くなるか |

**「双方が成立しません」と出ても、エラーではありません。**
この条件では交渉ではなく退去を前提に考えるべき、という答えです。

## 5. 計算式

```
査定賃料 A = 比較事例の㎡単価の中央値 × 対象物件の面積   （手入力で上書き可）

借主上限 = 現在賃料 × (24 + 5) / (24 + 1.25) = 現在賃料 × 1.1485
貸主下限 = (A × (24 − 空室月数) − 原状回復費用) / 25.25
逆転月   = (5 × 現在賃料 − 1.25 × 提示額) / (提示額 − 現在賃料)
```

**借主上限は査定賃料に依存しません。** 更新後賃料が現在賃料の約14.9%増を超えると、
借主は転居したほうが得になります。

この式が置いている仮定（転居費用5ヶ月分・更新料1.25ヶ月分・比較期間24ヶ月など）は、
すべて**実務感覚で置いた値**です。根拠と、実際の募集図面との差は
**[`docs/spec.md`](docs/spec.md) 第2章**に書いてあります。**使う前に一度読んでください。**

## 6. 困ったとき

| 症状 | 原因と対処 |
| --- | --- |
| `npm: command not found` | Node.js が入っていません。手順1へ |
| `Port 3000 is already in use` | すでに起動しています。ブラウザで http://localhost:3000 を開くか、`Ctrl`+`C` で止めてから起動し直してください |
| ファイルを選んでも何も出ない | シート名が「対象物件」「比較事例」になっているか確認してください。名前を変えると読めません |
| 「シート『○○』が見つかりません」 | 同上。テンプレートを再ダウンロードして書き直すのが確実です |
| 比較事例が赤くなって集計から外れる | 必須列（物件名・賃料・管理費・面積・募集元・確認日）のどれかが空です |
| 「査定賃料の自動算出には比較事例が5件必要」 | 事例を足すか、査定賃料を直接入力してください |
| 資料のボタンが押せない | 提示額が未入力です |

## 7. 開発者向け

```
npm test          # 90件
npm run typecheck
npm run build
npm run template  # 入力シートを再生成（python3 と openpyxl が必要）
```

| 場所 | 役割 |
| --- | --- |
| `src/core/v1/assumptions.ts` | **置いた仮定の全部。** 根拠と実データとの差をコメントに書いてある |
| `src/core/v1/model.ts` | 借主上限・貸主下限・逆転月 |
| `src/core/v1/assess.ts` | 査定賃料と入力の検証 |
| `src/core/v1/prompt.ts` | メール作成用の材料とプロンプト |
| `src/core/v1/schedule.ts` | 日付の整合確認 |
| `src/excel/columns.json` | 入力シートの列定義。**テンプレート生成と取り込みの唯一の正** |
| `src/core/legacy/` | Ver2 用。月次キャッシュフローと旧受入確認12件。**Ver1 の計算はここを通らない** |

計算は `src/core/v1/` に、画面にも保存にも依存しない純粋な処理として置いてあります。
同じ入力なら常に同じ数値になります。

## Ver1 が扱わないもの

PDFからの抽出（アプリの外でやります）／広告費・AD／新規礼金／転居費用の費目別入力／
比較期間の可変化／築年・階・向きの補正／面積基準の区別

理由と影響は [`docs/spec.md`](docs/spec.md) 第7章にあります。
