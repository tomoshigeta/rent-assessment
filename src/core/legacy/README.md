# legacy — Ver2 で使うコード

**Ver1 の計算はここを通らない。** `src/core/v1/` だけが使われる。

ここにあるのは、費用を月ごとに積み上げる仕組みと、その受入確認12件。
Ver1 は転居費用・更新料・比較期間をすべて固定値にしたため累計費用が一次式になり、
月次の積み上げが不要になった。費目別の入力を戻すときにここへ戻る。

| ファイル | 中身 |
| --- | --- |
| `scenario.ts` | 月ごとの費用・累計費用・契約時必要資金・預け金の扱い |
| `compare.ts` | 累計費用の逆転検出（再逆転・同額時点の区別を含む） |
| `bounds.ts` | 旧モデルの上下限。**この式が交差を起こした。使わないこと** |
| `build.ts` | 案件からシナリオを組み立てる |
| `__tests__/` | 旧仕様 §8 の受入確認12件ほか |

## テストを通したまま維持すること

12件は、実装してみないと気づかない落とし穴の記録である。

- 前家賃を初月家賃と二重計上しない
- 敷金を費用化せず、必要資金と返還予定に分ける
- 「同額」と「優劣の逆転」を区別する（同額でも優劣が変わらない場合がある）
- 更新料が賃料に連動する場合に再計算する
- 次期の更新料は 1 + k×契約期間 ヶ月目に立つ
- 記載のない金額を 0 円と確定しない

通らなくなった瞬間に、戻すときの価値が消える。

## bounds.ts を再利用しないこと

旧モデルの借主上限は「実在の転居候補との比較」で求めていた。
候補を選び直すだけで上限が動くため、査定として成立していない。
詳細は `docs/spec.md` の改訂履歴にある。
